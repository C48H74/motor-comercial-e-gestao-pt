# 2. Oferta e precificação

## 2.1 Anatomia da oferta

Toda oferta precisa fechar estes seis elementos. Falta de qualquer um = oferta vaga.

| Elemento | Pergunta que responde | Critério de qualidade |
|---|---|---|
| **Resultado** | o que muda na vida do cliente? | substantivo concreto + número quando existir |
| **Prazo** | em quanto tempo? | prazo real, não aspiracional |
| **Mecanismo** | por que o seu jeito funciona? | nome próprio para o método (dá propriedade) |
| **Prova** | quem já teve esse resultado? | nomeado e autorizado |
| **Risco** | o que acontece se não funcionar? | garantia com exposição calculada (§2.5) |
| **Preço** | quanto, em que formato? | ancorado na alternativa, não no seu custo |

### Sinais de oferta vaga (reescreva antes de seguir)
"solução completa" · "transformação digital" · "parceria estratégica" · "aumenta a produtividade"
**sem número** · "atendemos empresas de todos os tamanhos" · "sob medida para você" sem dizer o que
muda.

## 2.2 Os 6 modelos de precificação

Avalie sempre os seis e escolha **um** como principal. Modelos mistos são permitidos, mas precisam
ser declarados.

| Modelo | Quando serve | Risco para você |
|---|---|---|
| **Por projeto** (escopo fechado) | escopo claro, baixa mudança | escopo cresce, margem cai |
| **Por hora / dia** | escopo indefinido, consultoria | pune sua eficiência; cliente controla o ritmo |
| **Assinatura mensal** | valor contínuo, produto/serviço recorrente | precisa provar valor todo mês |
| **Por uso / resultado** | resultado mensurável e auditável | exige medição confiável e acordo de critério |
| **Por assento / usuário** | valor escala com adoção | se a adoção não acontecer, o cliente cancela |
| **Base + sucesso** | cliente quer dividir risco | fluxo de caixa e cobrança ficam complexos |

## 2.3 As 3 camadas — nunca uma só

Com **uma única opção**, a decisão do cliente vira binária: "compro ou não compro". Com três, vira
"qual eu compro". Isso reduz indecisão (ver JOLT em `references/03-metodologias-de-venda.md`).

| Camada | Papel | Como desenhar |
|---|---|---|
| **Essencial** | resolve a dor principal, sem extras | mínimo que entrega o resultado prometido |
| **Recomendada** | **a que você quer vender** | marque como recomendada — recomendação explícita reduz indecisão |
| **Completa** | âncora superior | faz a recomendada parecer razoável; não precisa ser a mais vendida |

**Erro comum:** colocar o melhor custo-benefício na camada mais barata. A camada recomendada deve
ser a de melhor margem **e** de melhor resultado para o cliente — se essas duas não coincidem, o
desenho está errado.

## 2.4 Economia unitária — obrigatória antes de apresentar

Para **cada** camada, calcule:

```
Custo direto de entrega   = horas × custo/hora + insumos + terceiros
Margem bruta              = preço − custo direto
Margem %                  = margem bruta / preço
Ponto de equilíbrio       = custo fixo alocado / margem bruta por unidade
```

**Regra dura:** camada com margem negativa ou com ponto de equilíbrio acima da sua capacidade
**não vai para a proposta**. Sem esse cálculo, você está vendendo para perder dinheiro.

## 2.5 Garantia com matemática de exposição

Antes de prometer qualquer garantia:

```
Exposição = (probabilidade de acionamento) × (custo de honrar)
```

- Se `Exposição > margem da camada` → **não ofereça essa garantia**, ou restrinja o gatilho.
- Garantias defensáveis: refazer sem custo **dentro do escopo escrito** · devolver a diferença
  mediante métrica acordada e auditável · período de saída com aviso · serviços profissionais
  incluídos até o valor.
- **Nunca prometa resultado que depende do cliente** (ex.: "você vai faturar X").

Enquadre a garantia como **depósito de confiança** (§1.3), não como desconto disfarçado.

## 2.6 Mecanismos de enquadramento

| Mecanismo | Como aplicar | Cuidado |
|---|---|---|
| **Ancoragem** | mostre a alternativa mais cara (inclusive "não fazer nada" e o custo do problema) antes do seu preço | a âncora precisa ser real e verificável |
| **Isca (decoy)** | a camada completa existe para orientar a escolha para a recomendada | não humilhe a camada completa; ela precisa ser defensável |
| **Enquadramento anual** | mostre o equivalente mensal **e** o desconto anual | deixe explícito o que o anual inclui |
| **Lançamento vs. escala** | preço de entrada menor com contrapartida declarada (ex.: feedback, estudo de caso) | data de fim real, não inventada |
| **Grandfathering** | cliente antigo mantém o preço quando o preço sobe | **diga isso em voz alta** — é depósito de confiança |

## 2.7 Checklist de revisão de preço

- [ ] A oferta tem os seis elementos de §2.1?
- [ ] O modelo escolhido está declarado e justificado?
- [ ] Existem três camadas, com a recomendada marcada?
- [ ] A economia unitária de cada camada foi calculada?
- [ ] A garantia (se houver) passou pela matemática de exposição?
- [ ] O preço está ancorado na alternativa do cliente, não no meu custo?
- [ ] Existe um caso de estudo **autorizado** para sustentar o valor?
- [ ] Se o cliente disser "está caro", eu sei qual número dele falta? (ver §4.3 de
  `references/04-outbound-e-objecoes.md`)
